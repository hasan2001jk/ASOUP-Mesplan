# Mesplan (:8687) — анализ и план

Обзор 2026-10-16, только чтение. Код не менялся.

## 1. Что это

Java 8, Gradle 8.5 (обёртка), Spring Boot 2.6.3, JPA, mssql-jdbc 8.4.1, Lombok.
БД `mesplan` на 198.1.2.246, пользователь `sa`. 6 сущностей: `orders`, `orderdetail`,
справочники `rodvag`, `przsob`, `conttypesize`.

## 2. Кто вызывает

Только раздел фронтенда `/oper/mesplan` (`MesplanService`), 4 вызова:

| Вызов | Где | Эндпойнт |
|---|---|---|
| Загрузка файла заявки | «Загрузка» | `POST /api/order/upload` |
| Справочник родов вагонов | «Ввод» | `GET /api/dictionaries/rodvag` |
| Признак собственности | «Ввод» | `GET /api/dictionaries/przsob` |
| Типоразмер контейнера | «Ввод» | `GET /api/dictionaries/conttypesize` |

Без вызывающих: `/api/order/date/{d}`, `/id/{id}`, `/save`, `/delete/{id}`,
`/api/orderdetails/save`, `/{id}/delete`, справочники по id, весь `/api/test/*`.
Примечание: фронтенд считает, что сохранения заявки нет, а `POST /api/order/save` есть —
форму «Ввод» можно будет подключить к нему, когда дойдёт очередь.

## 3. Находки

**M1. В исходном виде сервис не запускается.** В `application.properties` стоит
`server.ssl.enabled=true` без хранилища ключей. Сборка из исходника проходит
(`gradle bootJar`), запуск падает: `Could not load key store 'null'`. Проверено
в контейнере без сети, с тестовым конфигом.

**M2. На проде порт 8687 не отвечает** (16.10, соединение отклонено), тогда как
:8686 и :4646 с той же машины отвечают 200. Вероятно, служба не запущена — то есть
раздел МЕСПЛАН сейчас не работает вовсе. Нужно подтвердить на сервере.

**M3. Ответ загрузки — тот же конверт, что был в AsoupServer.** Успех отвечает
`200 {message: "Сообщение сохранено"}`, ошибка — `200 {message: "1"}` или `"2"`.
Фронтенд читает любой `{message}` как ошибку, поэтому успех показан бы красным,
а ошибка — непонятной цифрой. Исправлять так же, как AsoupServer §31: успех
`{result}`, ошибка — 400/502 с русским текстом.

**M4. Разбор файла хрупкий.** `getOrder` режет строку по `^` вручную; файл
неверной формы даёт `StringIndexOutOfBounds` → ответ «2» без пояснения. Нужны
проверка формата и понятная причина отказа. Тест — на образце настоящего файла.

**M5. Общие для всех служб пункты:** пароль `sa` в `application.properties`
(уже вне git), проверки токена нет, `@CrossOrigin` открыт, `show-sql=true`,
`TestController` в сборке, эндпойнты без вызывающих. Приём тот же, что в
AsoupServer и Backend-Asoup: пароль из переменной окружения + `RequiredSecrets`,
JWT-фильтр off/log/enforce, `@NoKnownClient`, удалить тестовый контроллер.

**M6. Тестов нет** (`src/test` отсутствует).

## 4. Что нужно от пользователя

1. Копия папки службы с прод-сервера (если она есть) — JAR, конфиг, логи
   обёртки. Положить в `docs/prod-copy/` (в .gitignore).
2. Подтверждение: запущена ли служба МЕСПЛАН вообще, и пользуется ли кто-то разделом.
3. 1-2 настоящих файла заявки для загрузки — для теста разбора.
4. Схема БД `mesplan` (скрипт без данных), как для AsoupServer.

## 5. План (после ответов)

1. Сравнить прод-JAR с исходником (если найдётся).
2. Конфиг: SSL выключить (или вынести в переменные), пароль из окружения.
3. M3 и M4 + тесты разбора на настоящих файлах.
4. JWT off/log/enforce, `@NoKnownClient`, удалить `TestController`, CI.
5. Проверка на стенде с Java 8u65 и пустой БД.
