# Mesplan (:8687) — анализ и план

Служба заявок МЕСПЛАН (месячный план перевозок). Java 8, Gradle, Spring Boot,
SQL Server 2005 (`mesplan` на 198.1.2.246). Вызывает только фронт Oper, раздел
`/oper/mesplan`. Ветка `dev`.

## 1. Как было (обзор 16.10.2026)

- **Служба на проде не работала.** Порт 8687 на .246 закрыт (подтвердил пользователь).
  Из исходника она и не могла запуститься: `server.ssl.enabled=true` без хранилища
  ключей → «Could not load key store 'null'».
- **С рабочей базой код не сходился.** Схема восстановлена из кэша IntelliJ
  (`docs/schema-2025-01-22.sql`). В `orders` нет колонки `header`, а «государство
  назначения» лежит в колонке `strbazn`; сущность ждала `header` и `strnazn`. Любое
  чтение и запись заявки давали бы «Invalid column name».
- **Строки администраций не сохранялись бы никогда:** `orderdetails.orderid` был
  отмечен `insertable=false` и на связи, и на поле — колонку не писал никто.
- **Ответ загрузки — конверт `{message}` и на успех, и на ошибку** (как было
  у AsoupServer, §31 там): успех показывался красным, ошибка — цифрой «1»/«2».
- Разбор файла резал строку вручную: неверный файл → «2» без пояснения; перевод
  строки в конце файла валил разбор; «Причина отказа» последней администрации
  без завершающего «^» терялась.
- Фронт: «Ввод» — заглушка с выключенной «Сохранить», одна строка администрации,
  в заявку не попадавшая; «Просмотр» — «в разработке».
- Общее со всеми службами: пароль `sa` в properties, нет проверки токена,
  `show-sql=true`, `TestController`, нет тестов.

Старая программа `docs/mesplan.exe` (Delphi, «mesplan2006», в git не кладётся) —
настольная, с таблицами dBase. Сервером не была; полезна как справка: таблицы
WORK/WORK1 совпадают с `orders`/`orderdetails`, в ней же были плановые сообщения
0304/0305/0306, которых в Java нет (см. §4).

## 3. Что нужно от пользователя

1. **Сверить схему с рабочей базой** (SSMS, только чтение):
   ```sql
   USE mesplan;
   SELECT TABLE_NAME, COLUMN_NAME, DATA_TYPE, CHARACTER_MAXIMUM_LENGTH, IS_NULLABLE
   FROM INFORMATION_SCHEMA.COLUMNS ORDER BY TABLE_NAME, ORDINAL_POSITION;
   SELECT @@VERSION;
   SELECT (SELECT COUNT(*) FROM orders) AS orders, (SELECT COUNT(*) FROM orderdetails) AS details,
          (SELECT COUNT(*) FROM rodvag) AS rodvag, (SELECT COUNT(*) FROM przsob) AS przsob,
          (SELECT COUNT(*) FROM conttypesize) AS conttypesize;
   ```
   Снимку 22.01.2025: если `strbazn` уже переименован или `header` добавлен —
   правка в одну строку в `entity/Order.java`. Пустые справочники — «Ввод»
   останется без списков.
2. **1–2 настоящих файла заявок** — разбор сделан по исходному коду, а не по живому
   файлу. Особенно: бывает ли в файле больше одной заявки (сейчас такой файл
   отклоняется с понятной причиной, а не обрезается) и какие значения в «Тип файла»
   (в базе 2 знака; прежняя форма предлагала PLAN/PL_E/PL_K — 4 знака, не помещались).
3. **Коды «Результата»** администрации — что значат 0/1/2. Сейчас поле — число,
   в «Просмотре» «ответили» = результат не 0.
4. **Нужен ли ответный файл** (старая программа сохраняла файл заявок с ответами)
   и плановые сообщения 0304/0305/0306 — их в Java не было; формат 0304–0306 виден
   в старой программе (`(:0304 …:)`), но без образцов не делаю.

## 4. Выкат

Служба новая для сервера (раньше не работала), фронт уже ходит на `:8687`.
Порядок (подробно — `docs/ВЫКАТ.md`, по-русски):

1. Сверка схемы (§3.1). Расходится — сначала поправить сущность.
2. Mesplan с `MESPLAN_AUTH_MODE=log` (или `off`, пока на проде старый Backend-Auth:
   его токены без ролей, и в enforce пользователи МЕСПЛАН получат 403).
3. Фронт с новым разделом.
4. После нового Backend-Auth и чистого журнала («был бы отклонён» нет) — `enforce`.
   ⚠ Фронт при любом 401 выходит из системы — неверный `JWT_SECRET` в enforce
   выкинет всех, кто откроет МЕСПЛАН. Поэтому сначала `log`.

Не код, а настройка: вход `sa` (сисадмин) → отдельный вход только к базе `mesplan`
с правами чтения/записи этих пяти таблиц.

## 5. Открыто

- CORS открыт (`@CrossOrigin`), как у остальных служб.
- Файл больше 2 МБ отклоняется до контроллера — без заголовка CORS браузер покажет
  «status 0», а не текст. Файлы заявок — килобайты; оставлено.
- Повторная загрузка того же файла создаёт вторую заявку (уникального признака
  в схеме нет). Если нужно — договориться, что считать одной заявкой.
